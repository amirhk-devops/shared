# راهنمای نصب و ارتقای سامانه هوش مصنوعی (AI Deployment Guide)

**مخاطب:** تیم پشتیبانی فنی و پشتیبانی محصول  
**سیستم‌عامل مقصد:** Linux  
**روش استقرار:** Docker Compose  
**نسخه ایمیج‌ها:** همیشه آخرین نسخه با تگ `latest`

---

## 1. معرفی ساختار نصب

در تمام مشتری‌ها، مسیرهای نصب باید مطابق استاندارد زیر باشند:

| مسیر | کاربرد |
|---|---|
| `/opt/chargoon/ai` | مسیر اصلی نصب و اجرای سرویس‌ها |
| `/opt/chargoon/ai-deploy` | محل قرارگیری فایل‌های Package و اسکریپت‌های استقرار |
| `/opt/chargoon/ai-deploy/backups` | نگهداری نسخه‌های پشتیبان |

**نکته مهم:** سرویس‌ها باید از مسیر `/opt/chargoon/ai` اجرا شوند. فایل‌های استقرار در مسیر `ai-deploy` قرار می‌گیرند و اسکریپت نصب، فایل‌های موردنیاز را به مسیر اصلی منتقل می‌کند.

ساختار کلی مسیر نصب:

```text
/opt/chargoon/
├── ai/
│   ├── .env
│   ├── .release-version
│   ├── configs/
│   ├── volumes/
│   ├── docker-compose.yml
│   ├── docker-compose-messagebus.yml
│   ├── docker-compose-referral.yml
│   └── docker-compose-control-panel.yml
│
└── ai-deploy/
    ├── deploy-ai-bootstrap.sh
    ├── deploy-ai-for-customer.sh
    ├── .release-version
    ├── configs/
    ├── volumes/
    ├── backups/
    └── docker-compose*.yml
```

> ساختار نهایی ممکن است با توجه به نسخه Package تغییر کند. فایل‌های Package را دستی ویرایش نکنید، مگر اینکه در دستورالعمل استقرار مشخص شده باشد.

---

## 2. فایل‌های موردنیاز نصب

فایل‌های به‌روز استقرار همیشه از مسیر زیر دریافت می‌شوند:

```text
\\appcs\Didgah Installation\AI-Installation\
```

فایل اصلی که باید به سرور مشتری منتقل شود:

```text
deploy-ai-bootstrap.sh
```

مسیر فایل‌های ایمیج سرویس‌ها در سناریوی انتقال دستی:

```text
\\appcs\Didgah Installation\AI-Installation\AIEngineImages
```

### قوانین دریافت فایل‌ها

1. همیشه آخرین نسخه فایل `deploy-ai-bootstrap.sh` را از مسیر اعلام‌شده دریافت کنید.
2. همیشه آخرین نسخه ایمیج‌ها را از پوشه `AIEngineImages` دریافت کنید.
3. ایمیج‌های سرویس‌ها باید با تگ `latest` باشند.
4. از نسخه‌های قدیمی باقی‌مانده روی سیستم خود یا مشتری استفاده نکنید.
5. فایل‌های نصب و ایمیج‌ها را از منابع دیگری دریافت نکنید.

---

## 3. بررسی پیش‌نیازهای سرور مشتری

قبل از شروع نصب، با کاربر `root` وارد سرور شوید.

```bash
sudo -i
```

### 3.1. بررسی سیستم‌عامل

```bash
cat /etc/os-release
```

### 3.2. بررسی فضای دیسک

```bash
df -h
```

فضای کافی برای دریافت ایمیج‌ها، استخراج Package و نگهداری داده‌های سرویس‌ها باید وجود داشته باشد.

### 3.3. بررسی Docker

```bash
docker --version
```

### 3.4. بررسی Docker Compose

```bash
docker compose version
```

### 3.5. بررسی وضعیت Docker

```bash
systemctl status docker
```

در صورت غیرفعال بودن سرویس:

```bash
systemctl start docker
systemctl enable docker
```

### 3.6. بررسی دسترسی به Registry

در صورتی که قرار است ایمیج‌ها مستقیماً از Registry دریافت شوند:

```bash
docker login devops.chargoon.net:8083
```

نام کاربری و رمز عبور باید از مسئول مربوطه دریافت شود.

در صورت موفقیت، پیام Login Succeeded نمایش داده می‌شود.

> اگر مشتری به اینترنت یا Registry داخلی دسترسی ندارد، از سناریوی انتقال دستی ایمیج‌ها استفاده کنید.

---

## 4. آماده‌سازی مسیرهای استاندارد نصب

مسیرهای اصلی را ایجاد کنید:

```bash
mkdir -p /opt/chargoon/ai
mkdir -p /opt/chargoon/ai-deploy
```

برای اجرای عملیات نصب، با کاربر `root` ادامه دهید.

فایل Bootstrap را در مسیر زیر قرار دهید:

```text
/opt/chargoon/ai-deploy/deploy-ai-bootstrap.sh
```

سپس مجوز اجرا بدهید:

```bash
chmod +x /opt/chargoon/ai-deploy/deploy-ai-bootstrap.sh
```

## 5. انتخاب روش دریافت ایمیج‌ها

سه حالت برای تأمین ایمیج‌ها در نظر گرفته شده است. با توجه به شرایط شبکه مشتری، یکی از روش‌های زیر را انتخاب کنید.

### سناریوی اول: دریافت ایمیج‌ها از Registry

<badge>روش پیشنهادی</badge>

در این حالت سرور مشتری باید به Registry دسترسی داشته باشد.

اطمینان حاصل کنید که لاگین انجام شده است:

```bash
docker login devops.chargoon.net:8083
```

سپس Bootstrap را با روش Registry اجرا کنید:

```bash
cd /opt/chargoon/ai-deploy

IMAGE_SOURCE=registry ./deploy-ai-bootstrap.sh
```

در این روش، اسکریپت مسئول دریافت Package Image و آماده‌سازی ایمیج‌های موردنیاز طبق فرآیند استقرار خواهد بود.

**این روش زمانی استفاده شود که:**

- سرور مشتری به Registry دسترسی دارد.
- دسترسی لازم برای دریافت ایمیج‌ها فراهم است.
- نیازی به انتقال دستی فایل‌های ایمیج نیست.

---

### سناریوی دوم: استفاده از ایمیج‌های از قبل موجود روی سرور

در این حالت ایمیج‌های موردنیاز قبلاً روی سرور وجود دارند.

ابتدا لیست ایمیج‌ها را بررسی کنید:

```bash
docker images
```

برای مشاهده ایمیج‌های AI:

```bash
docker images | grep -E 'chargoon-ai|message-bus'
```

توجه کنید که ایمیج‌ها باید با تگ `latest` موجود باشند.

اگر Package Image نیز قبلاً روی سرور بارگذاری شده باشد، Bootstrap را به شکل زیر اجرا کنید:

```bash
cd /opt/chargoon/ai-deploy

IMAGE_SOURCE=local ./deploy-ai-bootstrap.sh
```

**این روش زمانی استفاده شود که:**

- ایمیج Package روی سرور وجود دارد.
- ایمیج‌های سرویس‌ها نیز از قبل روی سرور بارگذاری شده‌اند.
- قرار نیست ایمیجی از Registry دریافت شود.

---

### سناریوی سوم: انتقال دستی فایل‌های ایمیج

این روش برای مشتریانی است که دسترسی مستقیم به Registry ندارند.

#### مرحله 1: دریافت فایل‌ها

از مسیر زیر آخرین نسخه فایل‌های ایمیج را دریافت کنید:

```text
\\appcs\Didgah Installation\AI-Installation\AIEngineImages
```

تمام فایل‌های موردنیاز نسخه جدید را به سرور مشتری منتقل کنید.

به‌عنوان مثال، مسیر مقصد را به شکل زیر در نظر بگیرید:

```text
/opt/chargoon/ai-deploy/images
```

#### مرحله 2: بررسی فایل‌های منتقل‌شده

```bash
ls -lh /opt/chargoon/ai-deploy/images/
```

#### مرحله 3: بارگذاری ایمیج‌ها

فایل‌های Docker Image با پسوند `tar` را بارگذاری کنید:

```bash
for file in /opt/chargoon/ai-deploy/images/*.tar; do
    [[ -f "$file" ]] || continue

    echo "Loading: $file"
    docker load -i "$file" || exit 1
done
```

پس از اتمام بارگذاری، ایمیج‌ها را بررسی کنید:

```bash
docker images
```

**نکته:** در این سناریو باید Package Image نیز روی سرور در دسترس باشد. اگر Package Image هم به‌صورت فایل منتقل شده است، آن را نیز با `docker load` بارگذاری کنید.

#### مرحله 4: اجرای Bootstrap

اگر تمام ایمیج‌های موردنیاز، شامل Package Image و ایمیج‌های سرویس‌ها، روی سرور بارگذاری شده‌اند:

```bash
cd /opt/chargoon/ai-deploy

IMAGE_SOURCE=local ./deploy-ai-bootstrap.sh
```

اگر از حالت `tar` در Bootstrap برای دریافت Package Image از فایل استفاده می‌کنید، باید فایل Package Image را در مسیر مورد انتظار همان نسخه از Bootstrap قرار دهید و از حالت زیر استفاده کنید:

```bash
IMAGE_SOURCE=tar ./deploy-ai-bootstrap.sh
```

> مسیر و نام فایل Package Image باید مطابق قرارداد نسخه Bootstrap باشد. فایل‌های ایمیج سرویس‌ها در پوشه `AIEngineImages` را با Package Image اشتباه نگیرید.

## 6. اجرای فرآیند نصب

پس از آماده‌سازی فایل‌ها و انتخاب روش دریافت ایمیج‌ها، نصب از طریق Bootstrap انجام می‌شود.

دستور اجرا:

```bash
cd /opt/chargoon/ai-deploy

IMAGE_SOURCE=registry ./deploy-ai-bootstrap.sh
```

در صورتی که از روش محلی استفاده می‌کنید:

```bash
IMAGE_SOURCE=local ./deploy-ai-bootstrap.sh
```

Bootstrap وظایف زیر را انجام می‌دهد:

1. بررسی دسترسی root.
2. بررسی Docker و Docker Compose.
3. آماده‌سازی Package Image بر اساس روش انتخاب‌شده.
4. استخراج Package Image.
5. دریافت فایل‌های Package.
6. بررسی نسخه Package.
7. قرار دادن فایل‌های موردنیاز در مسیر استاندارد `/opt/chargoon/ai-deploy`.
8. اجرای اسکریپت اصلی نصب با گزینه `--engine`.

پس از اجرای Bootstrap، ادامه فرآیند توسط اسکریپت اصلی انجام می‌شود.

**در طول فرآیند نصب، پنجره ترمینال را نبندید و منتظر پایان عملیات بمانید.**

---

## 7. مراحل داخلی نصب و ارتقا

اسکریپت اصلی فرآیند نصب را به ترتیب زیر اجرا می‌کند:

1. بررسی پیش‌نیازها و ایجاد Lock.
2. ایجاد مسیر Backup.
3. تشخیص وضعیت نصب قبلی.
4. تهیه نسخه پشتیبان از فایل‌های فعلی.
5. تهیه نسخه پشتیبان از ایمیج‌های فعلی.
6. آماده‌سازی ایمیج‌های نسخه جدید.
7. بررسی تطابق نسخه ایمیج‌ها با نسخه Package.
8. متوقف کردن سرویس‌های قبلی.
9. تهیه نسخه پشتیبان از Volumeهای فعلی.
10. آماده‌سازی فایل `.env` و Configها.
11. ایجاد دایرکتوری‌های موردنیاز Volumeها.
12. آماده‌سازی فایل‌های Volume.
13. آماده‌سازی Docker Network.
14. انتقال فایل‌های Compose جدید به مسیر اصلی.
15. اعتبارسنجی Docker Compose کنترل پنل.
16. اجرای Control Panel.
17. تکمیل فرآیند استقرار.

> در ارتقا، اطلاعات قبلی مشتری مانند `.env`، Configها و داده‌های Volume باید حفظ شوند. از حذف دستی این اطلاعات خودداری کنید.

## 8. بررسی نتیجه نصب

پس از پایان موفقیت‌آمیز نصب، موارد زیر را بررسی کنید.

### 8.1. مشاهده کانتینرها

```bash
docker ps -a
```

برای مشاهده خلاصه کانتینرها و وضعیت آن‌ها:

```bash
docker compose ls
```

### 8.2. بررسی ایمیج‌ها

```bash
docker images
```

ایمیج‌های سرویس باید با تگ `latest` باشند.

### 8.3. بررسی مسیر نصب

```bash
ls -la /opt/chargoon/ai
```

### 8.4. بررسی نسخه نصب‌شده

```bash
cat /opt/chargoon/ai/.release-version
```

### 8.5. بررسی شبکه Docker

```bash
docker network ls
```

شبکه مشترک پروژه باید ایجاد شده باشد.

### 8.6. بررسی لاگ Control Panel

ابتدا نام کانتینر را پیدا کنید:

```bash
docker ps -a
```

سپس:

```bash
docker logs --tail 100 -f CONTAINER_NAME
```

به‌جای `CONTAINER_NAME` نام واقعی کانتینر را قرار دهید.

## 9. دسترسی به Control Panel

پس از بالا آمدن موفقیت‌آمیز Control Panel، آدرس دسترسی را با توجه به تنظیمات `.env` و پورت تعریف‌شده در Compose بررسی کنید.

در صورت عدم دسترسی:

1. وضعیت کانتینر Control Panel را بررسی کنید.
2. لاگ کانتینر را مشاهده کنید.
3. پورت‌های تعریف‌شده در `.env` را بررسی کنید.
4. تنظیمات Firewall سرور را بررسی کنید.
5. ارتباط شبکه Docker را بررسی کنید.

## 10. خطاهای متداول و اقدامات اولیه

### خطای دسترسی Registry

اگر خطای Authentication یا عدم دسترسی دریافت شد:

```bash
docker login devops.chargoon.net:8083
```

دسترسی شبکه و اعتبارنامه را بررسی کنید.

### خطای نبودن ایمیج

```bash
docker images
```

بررسی کنید ایمیج موردنیاز با تگ `latest` وجود داشته باشد.

در صورت استفاده از انتقال دستی، مطمئن شوید تمام فایل‌های موردنیاز بارگذاری شده‌اند.

### خطای کمبود فضای دیسک

```bash
df -h
docker system df
```

قبل از پاک‌سازی هرگونه اطلاعات، وضعیت ایمیج‌ها و Volumeها را بررسی کنید.

**هشدار:** از اجرای دستورات زیر بدون بررسی و تأیید مسئول فنی خودداری کنید:

```bash
docker system prune -a
docker volume prune
rm -rf /opt/chargoon/ai/volumes
```

این دستورات ممکن است باعث حذف ایمیج‌ها یا اطلاعات مشتری شوند.

### خطای اجرای Bootstrap با کاربر غیر Root

در صورت مشاهده خطای زیر:

```text
ERROR: Run this script as root.
```

با کاربر Root وارد شوید:

```bash
sudo -i
```

سپس مجدداً Bootstrap را اجرا کنید.

### خطای اعتبارسنجی Compose

فایل‌های Compose و `.env` را بررسی کنید:

```bash
cd /opt/chargoon/ai

docker compose \
    --env-file .env \
    -f docker-compose-control-panel.yml \
    config --quiet
```

در صورت وجود خطا، متن کامل خطا را برای بررسی به تیم فنی ارسال کنید.

## 11. نکات مهم برای تیم پشتیبانی

- همیشه آخرین `deploy-ai-bootstrap.sh` را از مسیر اشتراکی دریافت کنید.
- همیشه آخرین ایمیج‌ها را از پوشه `AIEngineImages` دریافت کنید.
- تگ ایمیج‌های سرویس باید `latest` باشد.
- نصب و ارتقا باید با کاربر `root` انجام شود.
- مسیر استاندارد نصب `/opt/chargoon/ai` است.
- مسیر استاندارد فایل‌های استقرار `/opt/chargoon/ai-deploy` است.
- فایل‌های `.env` و Configهای مشتری را بدون هماهنگی تغییر ندهید.
- Volumeهای مشتری را حذف نکنید.
- در صورت بروز خطا، متن کامل خطا و لاگ مربوطه را نگهداری کنید.
- در صورت شکست فرآیند نصب یا ارتقا، بدون بررسی وضعیت Backup و سرویس‌ها اقدام به اجرای مجدد یا پاک‌سازی نکنید.
- از اجرای هم‌زمان چند فرآیند نصب روی یک سرور خودداری کنید.

## 12. چک‌لیست نهایی نصب

قبل از اعلام پایان کار، تمام موارد زیر را بررسی کنید:

- [ ] فایل Bootstrap از مسیر اشتراکی دریافت شده است.
- [ ] نسخه فایل Bootstrap به‌روز است.
- [ ] فضای دیسک کافی وجود دارد.
- [ ] Docker نصب و فعال است.
- [ ] Docker Compose در دسترس است.
- [ ] روش دریافت ایمیج‌ها مشخص شده است.
- [ ] تمام ایمیج‌های موردنیاز با تگ `latest` موجود هستند.
- [ ] Bootstrap بدون خطا اجرا شده است.
- [ ] فایل‌های Compose در مسیر `/opt/chargoon/ai` قرار دارند.
- [ ] فایل `.env` موجود و تنظیمات آن بررسی شده است.
- [ ] نسخه نصب‌شده در `.release-version` ثبت شده است.
- [ ] Docker Network ایجاد شده است.
- [ ] Control Panel با موفقیت اجرا شده است.
- [ ] وضعیت کانتینرها بررسی شده است.
- [ ] لاگ سرویس‌ها بررسی شده است.
- [ ] دسترسی به Control Panel تأیید شده است.

**پس از تأیید تمام موارد بالا، نصب یا ارتقا به پایان رسیده است.**
